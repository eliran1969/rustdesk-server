# בדיקת קבלה לשלב 2 - ארגון (משתמשים, קבוצות, מכשירים)

תאריך הריצה: 2026-11-15

## מה נבדק ואיך

הבדיקה האוטומטית מפעילה שרת hbbs+hbbr זמני בתיקייה זמנית (מסד נתונים נפרד, בלי לגעת בשרת האמיתי או ב-RustDesk שמותקן אצלך), ומריצה נגדו את סקריפטי הניהול האמיתיים של RustDesk (`users.py`, `user-groups.py`, `device-groups.py`, `devices.py`). בנוסף היא מדמה מחשב-לקוח ופועלת כמו הלקוח. בסוף היא מכבה הכול ומוחקת את התיקייה הזמנית.

להרצה חוזרת: `python -I docs/webconsole/phase2-acceptance-check.py --skip-build`

## הערות

- הסקריפט `user-groups.py` יוצר קבוצה בפקודה `add` (לא `create`).
- משתמש רגיל שנכנס ל-`/api/devices` רואה רק את המכשירים ששויכו אליו (כמתוכנן משלב 1).
- חוקי הגישה נשמרים ומשפיעים על הרשימות בלבד; אכיפה בחיבור עצמו תגיע בשלב 5.
- "השבתת מכשיר" רק מסמנת אותו במסוף, והיא עדיין לא חוסמת חיבורים (זה יגיע בשלב מאוחר יותר). מכשיר שמחובר בזמן שמוחקים אותו יופיע שוב, כמכשיר חדש, ברגע שיתחבר מחדש. הממשק מציג הסבר על כך ליד פעולות ההשבתה והמחיקה.

## צ'קליסט ידני (עבורך)

סמן V אחרי שבדקת. יש להריץ את השרת (גרסה מקומית או הסינולוגי) ולהתחבר ב-`http://<כתובת-השרת>:21114`.

- [ ] כניסה ראשונה כ-admin מחייבת החלפת סיסמה, ואחריה המסכים נפתחים.
- [ ] המסכים מופיעים בעברית (מימין לשמאל) ומתחלפים לאנגלית (משמאל לימין) בלי טקסט שנשאר בשפה הלא נכונה.
- [ ] משתמשים: הוספה, עריכה, השבתה, הפעלה ומחיקה עובדות, וההודעות ברורות.
- [ ] קבוצות משתמשים: יצירה עם חוקי גישה, שינוי שם, הוספת משתמשים, ומחיקה (קבוצה לא ריקה מסרבת עם הסבר).
- [ ] קבוצות מכשירים: יצירה, הוספת והסרת מכשירים, מחיקה.
- [ ] מכשירים: עריכת שם תצוגה והערה, שיוך למשתמש ולקבוצה, פעולה על כמה מכשירים יחד (batch), השבתה, ומחיקה של מכשיר מושבת.
- [ ] בלקוח RustDesk אמיתי (רק אחרי שתחליט להפנות אותו לשרת הזה): נכנסים עם משתמש רגיל, ובטאב "קבוצה" רואים רק את המשתמשים והמכשירים שחוקי הגישה מתירים.
- [ ] משתמש רגיל שפותח את מסכי הניהול ב-`/users` או `/devices` לא יכול לנהל משתמשים אחרים.
